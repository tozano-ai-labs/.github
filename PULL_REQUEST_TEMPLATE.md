## Résumé

Décrivez brièvement le changement et son objectif.

## Type de changement

- [ ] ✨ feat - Nouvelle fonctionnalité
- [ ] 🐛 fix - Correction de bug
- [ ] 📚 docs - Documentation uniquement
- [ ] ♻️ refactor - Réorganisation sans changement de comportement
- [ ] ✅ test - Ajout ou correction de tests
- [ ] 🔧 chore - Outillage, configuration
- [ ] ⚡ perf - Amélioration des performances
- [ ] 🎨 style - Mise en forme / UI
- [ ] 📦 build - Build, empaquetage, dépendances
- [ ] 🚑 ci - Intégration continue
- [ ] 🔒 security - Sécurité / données personnelles
- [ ] ⏪ revert - Annulation d'un changement
- [ ] 🧪 test-wip - Test en cours (à finaliser)

## Checklist

- [ ] Tests ajoutés ou mis à jour
- [ ] Aucun secret en clair (tokens, clés, mots de passe)
- [ ] Impact RGPD : non / oui (si oui, items concernés listés ci-dessous)
  - [ ] Minimisation des données
  - [ ] Conservation / durée de rétention
  - [ ] Droits des personnes (accès, rectification, effacement)
- [ ] Impact sur les prompts/logs IA : non / oui (si oui, précisé ci-dessous)
- [ ] Documentation mise à jour (README, docs/)
- [ ] Changements conformes aux règles du dépôt (cf. [ai-template](https://github.com/tozano-ai-labs/ai-template))

**Important :** Le titre de la Pull Request doit suivre le format `<gitmoji> <type>(<scope>): <description>` (72 caractères max). Il deviendra le message de commit sur `main` lors du squash merge.
